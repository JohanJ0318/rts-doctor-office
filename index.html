📋 Project Overview

This embedded system simulates a medical imaging facility's patient flow management using an ESP32 microcontroller and FreeRTOS. The system manages patient check-in, doctor availability, and X-ray positioning with hard real-time guarantees—ensuring that critical safety deadlines are always met.

Built for OrlandoHealth MedTech Solutions, this prototype demonstrates how real-time operating systems enable predictable, deterministic behavior in life-critical medical applications where timing failures could endanger patient safety.

Why Real-Time Matters: In a medical imaging facility, missing a timing deadline could mean scanning a patient in the wrong position (radiation exposure risk), losing patients from the queue (HIPAA violations), or creating cascading delays that affect dozens of scheduled appointments.

✨ Key Features

🔘 Patient Check-In

ISR-driven button press system with hardware debouncing. Binary semaphore ensures one patient per press, preventing queue corruption.

👥 Queue Management

Manages up to 200 patients with two concurrent doctors using counting semaphores. Prevents double-booking and ensures FIFO order.

📏 X-Ray Positioning

Ultrasonic sensor (HC-SR04) verifies patient distance (100-375cm safe zone). Highest priority task ensures life-safety compliance.

⏱️ Real-Time Guarantees

FreeRTOS preemptive scheduling with priority-based task execution. Logic analyzer proves all hard deadlines met with <5ms jitter.

🔧 Technical Implementation

Hardware Components

  • ESP32 DevKit C V4 microcontroller
  • 2× LEDs (office sign, check-in indicator)
  • HC-SR04 ultrasonic sensor (positioning)
  • Push button (patient check-in)
  • Piezo buzzer (patient notification)
  • Logic analyzer (timing verification)

Software Architecture

  • 4 FreeRTOS Tasks: doctor_office_sign, service_button, waiting_room, Xray_Scan
  • 1 ISR: button_isr_handler (hardware interrupt)
  • 5 Synchronization Primitives: Binary semaphore, mutex, counting semaphore, queues (×2)
  • Priority Scheme: Xray_Scan (4-highest), waiting_room (3), service_button (3), office_sign (1-lowest)

📊 Performance Results

Timing Analysis

  • Xray_Scan Period: 500ms ±5ms (1% jitter)
  • Queue Processing: <50ms latency (90% margin)
  • ISR Response: <10µs (button press)
  • Stress Test: 10 patients, 2 doctors, no deadline misses

Hard Deadline Compliance

Logic analyzer verification shows the Xray_Scan task maintains consistent 500ms intervals even under maximum load (both doctors busy, full queue). Timestamp logs prove deterministic behavior: 326150ms → 326650ms → 327150ms.
